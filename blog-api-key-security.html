網站資安／API 基礎

最後更新：2026 年 10 月 16 日

API 是什麼？API Key 外洩的資安風險與防護方法

從 API 基本運作、常見網站應用，到 API Key 的安全管理與外洩應變。

這次的經驗也讓我想探討平常開發網站時容易忽略的資安問題。相信很多人在使用 ChatGPT 時，都曾經聽過「API」這個名詞，但不一定真正了解它的用途。

甚至有人可能會以為，只要訂閱了 ChatGPT Plus，就能免費使用 OpenAI 的 API。其實，這是兩件不同的事情！

今天就從基本概念開始，帶大家了解 API 的運作原理、實際應用，以及 API Key 外洩可能造成的資安問題。

一、API 是什麼？為什麼網站需要 API？

API 的全名為 Application Programming Interface，中文稱為「應用程式介面」。

簡單來說，API 就是讓不同軟體、網站或系統之間，可以互相溝通、交換資料及使用功能的橋樑。

我們可以把 API 想像成餐廳裡的服務生。假設今天你到餐廳吃飯，想要點一份義大利麵，你不需要自己走進廚房料理，而是透過服務生將需求傳達給廚房。當廚房完成餐點後，服務生再將料理送到你面前。

API 的運作概念也是如此。當網站需要使用另一個系統的功能時，就能透過 API 發送請求，由對方系統處理後，再將結果回傳。

因此，開發者不需要重新建立每一項功能，就能使用其他平台提供的技術服務。這也是為什麼 API 已經成為現代網站與應用程式開發中不可或缺的重要工具。

二、API 是如何運作的？

了解 API 是什麼之後，接下來就要認識 API 的基本運作方式。一般而言，API 的資料交換可以分成兩個階段：Request（請求）與 Response（回應）。

例如，當你進入購物網站，想查看某項商品的價格與庫存資訊時，網站會向伺服器發送請求。伺服器收到請求後，會依照指定的內容進行處理，再將商品資訊回傳至網站。

整個流程可以簡單理解為：

  1. 使用者操作網站，提出資料需求。
  2. 網站透過 API 向伺服器發送請求。
  3. 伺服器接收請求並進行處理。
  4. 伺服器將結果回傳給網站。
  5. 網站呈現資料，讓使用者查看。

透過這樣的方式，不同系統即使使用不同的程式語言或技術架構，仍然可以依照約定好的介面進行資料交換。

三、API 在日常生活中有哪些應用？

API 並不是只有工程師才會接觸的技術，我們每天使用的許多網站與 APP，背後都有 API 的應用。以下整理四種常見的 API 使用情境。

1. LINE 快速登入

當你進入購物網站，看到「使用 LINE 登入」的按鈕時，背後就涉及 LINE 提供的登入授權服務。網站在取得使用者授權後，可以透過相關介面完成身分驗證，讓使用者不必重新註冊另一組帳號密碼。

2. Google Maps 地圖服務

許多餐廳、旅館與企業網站，都會整合 Google Maps 地圖功能。透過 Google Maps Platform 提供的 API，開發者可以將地圖、地點搜尋等功能整合進網站，不必自行建立完整的地圖系統。

3. 電商金流與訂單管理

當消費者在購物網站完成付款後，網站可以透過第三方金流服務提供的 API 或通知機制，取得付款結果並更新訂單狀態。如此一來，就能減少人工核對付款資訊的時間，提高訂單處理效率。

4. AI 智慧客服

隨著 AI 技術發展，越來越多企業開始將 AI 功能整合進網站。例如，開發者可以透過 OpenAI API，讓顧客直接在網站上詢問商品問題，並由 AI 協助提供回覆。

這也是 API 的主要價值之一：降低開發成本、整合不同服務，並提升使用者體驗。

四、什麼是 API Key？為什麼需要妥善保護？

當開發者需要串接第三方 API 時，部分服務會要求提供 API Key，也就是「API 金鑰」。

你可以將 API Key 想像成一把數位鑰匙。當程式向 API 服務發送請求時，系統可以透過金鑰識別呼叫者，並根據相關權限設定，決定是否提供服務。

API Key、OAuth 2.0 與 JWT 有什麼差別？

API Key 常用於系統對系統的服務識別；OAuth 2.0 著重於授權第三方應用程式取得有限權限；JWT 則是一種可攜帶簽章資訊的 Token 格式。實際選擇仍應依照使用情境、資料敏感程度與權限需求決定。

OAuth 2.0 與 PKCE 授權流程

在公開客戶端的 OAuth 2.0 流程中，PKCE 會搭配一次性的授權碼與 code_verifier，降低授權碼遭攔截後被直接交換 Token 的風險。實際部署仍需依照授權伺服器與客戶端類型完成安全設定。

例如，當開發者使用 OpenAI API 時，可以透過 API Key 驗證請求，讓自己的程式使用特定的 AI 模型服務。

需要注意的是，ChatGPT 訂閱服務與 OpenAI API 採用不同的計費方式。即使已經訂閱 ChatGPT Plus，也不代表可以免費使用付費的 OpenAI API。

API 的費用通常會受到模型種類、使用量與計費規則影響。因此，如果付費 API Key 不小心外洩，其他人就可能利用這組金鑰發送請求，進而產生非預期的費用。

不過，未授權扣款不一定代表 API Key 遭到外洩，也可能涉及帳號遭存取、付款資訊遭冒用或其他帳務問題，仍需進一步確認原因。

五、如果 API Key 外洩，會發生什麼事？

API Key 外洩的情況，可能比我們想像中更加常見。尤其對經常使用 GitHub、第三方服務或多人協作工具的開發者而言，更需要留意以下三種常見情境。

1. 直接將 API Key 寫在程式碼中（Hardcoding）

部分開發者為了方便測試，可能直接將 API Key 寫在 JavaScript 程式碼，或其他未受到妥善保護的設定檔中。如果這些程式碼被公開，其他人就可能取得金鑰，並使用相關 API 服務。

2. 不小心將 API Key 上傳至 GitHub

當開發者透過 Git Push 上傳程式碼時，如果沒有設定好 .gitignore，就可能不小心將包含 API Key 的 .env 檔案一起上傳。

更需要注意的是，即使後來刪除了檔案中的金鑰，過去的 Git 提交紀錄仍可能保留相關資訊。因此，一旦發現金鑰曾經公開，應立即撤銷並重新建立，而不是單純刪除檔案。

3. 在 Slack 或 Notion 等平台分享金鑰

除了程式碼之外，團隊協作平台也可能成為金鑰外洩的途徑。例如，直接在 Slack 群組中貼上 API Key，或將金鑰存放在多人共用的 Notion 頁面。

如果存取權限沒有妥善管理，就可能讓不應取得金鑰的人接觸到敏感資訊。

API Key 外洩可能造成的三大後果

第一，帳單突然暴漲。如果外洩的是付費 API Key，攻擊者可能大量呼叫 API，使帳號在短時間內產生高額使用費用。

第二，敏感資料遭到存取。如果金鑰具備讀取敏感資料的權限，攻擊者就可能利用這組金鑰取得原本受到保護的資訊。實際影響取決於金鑰的權限範圍。

第三，網站或系統服務中斷。當大量異常請求耗盡 API 使用額度，或觸發 Rate Limit（速率限制）時，可能使正常使用者無法順利取得服務。

因此，API Key 不應只是被視為普通的設定參數，而是需要妥善管理的重要安全憑證。

六、如何避免 API Key 外洩？五項安全防護措施

為了降低 API Key 外洩造成的風險，開發者可以從以下五個方向建立基本防護機制。

1. 使用環境變數管理金鑰

避免直接將 API Key 寫在公開的前端程式碼中。可以透過環境變數與可信任的後端環境管理金鑰，正式環境則可以使用主機平台提供的 Secrets 管理功能。

2. 設定 IP 白名單與速率限制

如果 API 服務支援，可以限制允許呼叫的來源 IP，以及一定時間內能夠發送的請求數量。即使金鑰不幸外洩，也能在一定程度上降低遭到濫用的風險。

3. 遵循最小權限原則

不同網站、專案與系統，應盡量使用獨立的 API Key。同時只開放實際需要的存取權限，避免單一金鑰具備過多功能。

4. 定期檢查與更換金鑰

除了依照風險與服務政策定期檢查金鑰之外，一旦懷疑金鑰遭到外洩，就應立即撤銷並更換。

5. 建立 API 使用量監控

定期檢查 API 的使用量、請求頻率與費用變化，並設定異常警示。需要注意的是，部分平台的預算提醒不一定會自動停止 API 使用，因此仍需確認服務提供者的實際限制機制。

七、如果 API Key 真的外洩，該怎麼辦？

如果發現 API Key 疑似遭到濫用，可以參考以下四個階段進行緊急處理。

第一階段：立即止血（0～5 分鐘）

立即撤銷或停用疑似外洩的 API Key，避免持續產生未經授權的請求。

第二階段：檢查異常紀錄（5～15 分鐘）

檢查 API 使用量、呼叫紀錄與相關帳務資訊，確認是否出現異常請求。

第三階段：更換金鑰（15～60 分鐘）

重新建立 API Key，更新後端環境變數及相關服務設定，並確認系統恢復正常。

第四階段：調查與加固（1～24 小時）

檢查 GitHub、程式碼、設定檔及團隊協作平台，找出可能的外洩來源，並補強金鑰管理與權限控制措施。

以上時間屬於建議性的應變目標，實際處理順序與所需時間仍應依事件嚴重程度調整。

如果涉及 OpenAI 未授權扣款，也應保留交易紀錄，並透過 OpenAI 官方客服及發卡銀行處理相關帳務問題。

八、結語：API 不只是開發工具，更需要安全管理

經過這次 OpenAI 未授權扣款事件，我開始重新思考，自己在網站開發過程中，是否真的有妥善管理每一項第三方服務。

以前在開發網站時，可能比較在意網站能不能正常運作、功能是否完整，以及使用者操作是否方便。但隨著接觸的第三方服務越來越多，我也逐漸發現：

一個好的網站，不只是功能能夠正常運作，更必須具備安全、穩定與可管理的系統架構。

API 確實能夠提升開發效率，讓我們不需要從零開始，就能整合會員登入、金流、物流及 AI 等功能。

但在享受便利的同時，開發者也需要重視金鑰管理、存取權限與使用成本。

常見問題 FAQ

Q1：API 是什麼？一般人需要了解嗎？

API 是讓不同軟體與系統之間進行資料交換及功能整合的介面。即使不會寫程式，了解 API 也有助於理解 LINE 登入、線上付款、地圖及 AI 等網站功能的運作方式。

Q2：API Key 是什麼？和密碼一樣嗎？

API Key 是用來識別 API 請求來源的憑證。雖然與密碼具有部分相似用途，但兩者的驗證機制與權限範圍不一定相同。需要保密的 API Key 應避免公開。

Q3：ChatGPT Plus 有包含 OpenAI API 費用嗎？

沒有。ChatGPT 訂閱服務與 OpenAI API 是不同的產品及計費系統。即使已經訂閱 ChatGPT Plus，使用付費 API 時仍可能產生額外費用。

Q4：API Key 外洩後，只要刪除程式碼就安全了嗎？

不一定。如果金鑰曾經上傳到公開的 GitHub Repository，過去的提交紀錄可能仍保留相關資訊。建議立即撤銷外洩金鑰並重新建立。

Q5：如何確認 OpenAI API 是否產生異常費用？

可以登入 OpenAI API 平台，檢查使用量與帳務資訊。如果發現不明費用，應保留交易紀錄，確認是否涉及未經授權的 API 使用，並聯繫官方客服處理。
